# Namo 架构与业务契约

Namo 是本地 Agent 任务网关。飞书 / Lark 提供对话入口，本地工作台提供管理，CLI 提供安装维护。官方 Codex app-server 管理推理、原生上下文和工具执行；Namo 管理身份、消息、任务、权限、调度、证据与交付。其他执行器目前只有发现能力。

技术栈为 TypeScript、Node.js 24.15+、node:sqlite、飞书官方 SDK、React、Radix Themes 和 Vite。源码数据库版本见 `src/store.ts` 的 `SCHEMA_VERSION`（当前为 8）；该值不代表实际在线实例版本。

## 对象与主链路

- 聊天 / 话题：输入与回复的位置，不等于 Agent session。
- 项目：已授权的真实目录与权限范围。
- 工作线：关联持续目标和任务，不默认共享所有历史。
- 任务：一次可验收工作，保留来源、操作者、修订、执行与投递记录。
- Agent session：执行器上下文，可在符合归属与范围时续接。

主链路为：校验系统身份 → 持久化入站 → 关联材料 / 工作线 / 任务 → 调度独立 runner → 保存执行结果 → 持久化出站 → 飞书投递。管理 API 复用同一业务存储和契约。

## 入站、材料与修订

先持久接受再确认飞书事件。引用、转发和附件只作为有来源的材料，不改变用户身份或权限。慢速材料解析不阻塞入站落库；资源描述不等于已读正文。支持类型与预算见[材料契约](materials.md)。

独立材料按用户、话题、项目及权限指纹关联，暂存 10 分钟，至多 30 条，组合输入上限 80000 字符。未知引用不自动抓取或猜测；群旁听与离线历史补拉未实现。

修订通过任务编号或本人任务引用关联。领取时冻结输入版本；运行中经执行器追加，记录 submitting、accepted、rejected、not_active 或 unknown。接受不代表已经完成，结果不明不重送。存在歧义时询问，不能猜测关联。

## 调度与运行

保留同聊天串行、全局并发上限，以及同真实目录和父子目录互斥。任务固定项目和权限快照；默认项目改变不能重定向已有任务，权限变化须重新校验。

接收服务与 runner 分离。接收服务重启重新关联原运行，不自动重新调用模型；失联保留占位，核对进程与外部效果后才解除。取消只中断对应执行，不撤销已发生操作。详见[独立运行](runner.md)。

人工等待释放执行资源并保留同聊天顺序屏障，回答须匹配原用户、话题和等待版本。它只收集事实或选择，不构成外部操作审批。详见[人工等待](waits.md)。GitHub 固定 HEAD 的检查等待有独立状态和适配器，见[外部等待](external-waits.md)。

## 上下文与授权

档案、助手偏好和范围记忆在新运行采用有界版本快照；恢复已有 runner 使用原持久化 prompt。身份来自系统事件，正文姓名不参与身份推断。当前明确要求优先于偏好，但不能扩大权限。

档案默认不注入，显式开启且符合本人私聊文字条件后使用；群聊不注入私人档案。记忆按 owner / project / chat 过滤，不从普通聊天自动写入。见[助手与档案](assistant-settings.md)、[记忆与交接](memory.md)。

推送入口绑定确切任务、目标、提交和有效期，仅提供有限保护；不代表所有网络与凭据路径都被强制隔离。见[Git 审批](approvals.md)。迁移来源的权限、任务或授权不能自动继承，见[OpenClaw 迁移](openclaw-migration.md)。

## 结果、投递与恢复

模型完成、平台接受和用户收到 / 已读是不同事实。结果先保存，再投递；投递失败不重跑模型，发送未知不盲重试。展示层只转换副本，不将模型正文当卡片 JSON 或操作授权。见[日常回复](chat-experience.md)。

执行证据是有容量限制的事件投影，不保存完整工具参数、输出或思考过程；退出码与文件存在性不能证明内容正确。见[执行证据](result-evidence.md)。

异常核对记录操作者、快照、依据与动作，幂等提交。人工确认收到不伪造平台回执，重发只处理保存的指定结果，执行核对不改写原结论或自动重跑。见[运维](operations.md#人工核对与受控处理)。

## 本地管理与发布

浏览器代码仅导入安全契约，不导入 Node、SQLite 或原始配置。管理服务绑定 loopback，校验 Host / Origin，使用单次启动授权、HttpOnly 会话和 CSP；凭据不返回页面。配置保存与应用分离，写入须通过版本冲突、兼容性和空闲检查。

发布快照包含生产依赖与 UI 资源，接收端和新 runner 使用同一版本。开发构建不替换服务快照。升级保留历史，旧版不能直接消费新库，回退不能覆盖升级后新增消息或重放未知操作。见[发布隔离](release-isolation.md)。

历史版本和验证记录由[文档索引](README.md#历史记录)统一导航，剩余工作见[后续计划](development-plan.md)。
