# 任务结果与执行证据

本批为 M2 的结果字段补充。需要单独升级接收服务，才会开始记录新任务；旧任务不回填执行证据。

## 可以看到什么

工作台任务详情包含文件变更、命令执行、产物与提交线索，以及原答复和投递记录。飞书文字与固定结果卡片附上有长度限制的执行摘要；详情命令 `/task` 也包含已保存记录。

| 记录 | 来源与含义 |
| --- | --- |
| 文件变更 | Codex 文件补丁事件的项目相对路径、增删改 / 移动及执行状态；失败或被拒绝的补丁不表示已修改 |
| 命令执行 | Codex 命令事件的固定标签、项目相对目录、退出码和耗时；不保存完整命令或参数 |
| 产物线索 | 成功补丁中的新增文件、图片生成事件的保存路径；结束时仅检查是否为项目内文件，不检查内容质量，也不开放下载接口 |
| Git HEAD | 在真实项目根目录开始和结束时读取 HEAD；变化只证明两个快照不同，不证明提交作者、任务归属、推送或部署成功 |
| 受阻与缺口 | 任务原有错误类别、命令 / 补丁失败或拒绝、无完成回执、部分采集与未知状态分别展示 |

退出码 0 不等于业务验收通过；退出码非零也不能单独推断整个任务失败。记录不会从模型答复中的“测试通过”“已生成文件”等文字推导。未观察到补丁也不表示没有修改，脚本、MCP 和其他工具的文件操作尚未完整覆盖。当前不能提供全面的改动清单、测试报告或构建产物索引。

## 记录与保护

- 依据 [官方 app-server 事件协议](https://learn.chatgpt.com/docs/app-server)，监听 `item/started`、`item/completed` 和 `turn/completed`，同时核对 thread 与 turn。快速完成时先缓存有限的投影，收到 `turn/start` 回执后才归入对应运行。
- 只保存命令的固定识别标签。完整 shell 文本、参数、标准输出 / 错误、补丁内容、工具参数 / 返回值及模型思考不进入证据库。
- 路径必须位于项目内，排除配置禁止路径、常见凭据文件以及通往项目外的符号链接；已知密钥或控制字符出现时不展示该路径。路径过滤不是文件内容审计。
- 每次运行最多保存 60 个执行项，每个补丁最多 8 个文件，展示路径最多 240 字符。达到限制或遇到未支持工具时明确提示部分记录；仍可更新已保存执行项的完成状态。
- 每个事件投影及时持久化。schema 4 中，运行结束的证据、任务状态和出站答复处于同一事务；schema 5 的独立 runner 先原子保存证据终态与运行结果，再由接收服务原子归档任务与出站答复，详见[独立运行进程](runner.md)。失败、取消或重启不会删除此前证据，也不会为了补齐证据自动重跑任务。
- `/task` 沿用本人、本聊天的归属校验；工作台沿用本机授权和同源保护。没有新增文件下载或任意路径读取 API。

## 升级与验证

schema 4 新增 `run_evidence`，以运行编号关联 `task_runs`，不修改原有表的业务字段。只读查看 schema 3 不触发迁移；历史运行显示无采集记录。管理写操作继续要求当前 schema，因此新版工作台连接旧实例时须先完成受控升级才能写入。

升级前停止并确认旧接收端退出，备份配置和完整数据目录及 SQLite 一致性快照，再启动新版；不得启动同应用的第二个接收端。旧二进制不能打开 schema 4，回退必须核对升级后的新增数据与外部效果，不能直接覆盖当前库。

本批隔离测试覆盖：事件与运行归属、快速完成、失败 / 取消与未知投递、崩溃后的部分证据、重复事件与上限、路径及内容排除、Git 快照、schema 3 升级保留。协议 smoke 只验证握手、官方登录与权限，不代表真实模型工具事件或飞书端到端验收已通过。

2026-10-26 已在授权升级的既有实例完成真实私聊验收：文件补丁和产物内容、命令退出码 0 / 7、执行证据落库、结果卡片平台回读、工作台任务 API 及“查看状态”真实回调均通过，用户确认收到。测试文件核验后已清理，证据保留；详细范围与未覆盖项见 [M2 验收](m2-verification.md#真实飞书执行证据验收)。
