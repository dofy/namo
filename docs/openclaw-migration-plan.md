# 从 OpenClaw 迁移

更新：2026-10-26。对应[主计划](development-plan.md)的 R2，已确认需求、尚未实现。本文保留迁移范围与验收要求，交付顺序以主计划为准。

## 交付拆分

先交付兼容检查与导入预览，再交付所选应用的受控接管与回退。首批只承诺经真实样本核验的来源版本和字段；记忆可以保留为待审阅材料，启用依赖 R6，不阻塞基本配置迁移。

## 范围与验收

目标：正在使用 OpenClaw 的用户安装 Namo 时，尽量复用兼容的飞书机器人配置、项目设置和记忆，减少重新填写与重复配置。首版提供一次性、可恢复的迁移，不默认长期双向同步，也不将迁移工具等同于后续 OpenClaw 执行器接入。

- [ ] 在 `namo init` 的飞书配置步骤提供“配置新机器人 / 从 OpenClaw 迁移”入口；允许已有 Namo 安装再次进入迁移向导。探测本机来源并允许指定路径，多实例、多应用时必须明确选中来源和目标。
- [ ] 先只读探测来源版本与格式，形成兼容清单：可直接迁移、需转换或确认、不支持、无法读取分别展示。未知格式不能猜测字段后直接覆盖；具体支持版本和字段映射在实现时核验并记录。
- [ ] 优先迁移所选飞书应用的 App ID、App Secret 或凭据引用、飞书 / Lark 区域及兼容的消息接入设置。凭据仅在本机受保护存储间处理，界面和报告只显示脱敏摘要；不可解析的凭据引用引导用户补齐，不输出原值。
- [ ] 尽量转换项目目录、默认项目、消息触发方式及身份规则；校验目录存在性和身份所属应用。白名单、群聊范围、联网及文件访问权限须单独核对，不照搬通配授权或扩大 Namo 默认权限；已有配置冲突逐项展示，禁止静默覆盖。
- [ ] 盘点可迁移的助手性格、用户偏好、项目知识、记忆文件及历史摘要，保留来源、所属用户 / 项目、可见范围与导入版本；性格映射依赖 R1 助手设置，记忆生效依赖 R6。尚无对应能力的资料只保存为受保护、待审阅的迁移材料，并明确“已保留，尚未生效”；归属不明的私聊资料不能直接变成全局记忆。
- [ ] 明确不直接继承来源中的授权指令、待执行任务、定时任务、插件可执行代码、模型登录凭据或第三方网关设置。无法转换的内容列出原因与后续操作；历史聊天或摘要不伪装成可原样续接的 Codex session，执行器仍完成独立官方登录与探针。
- [ ] 写入前展示迁移预览、冲突处理和接管影响，备份目标配置与必要数据，记录迁移进度、来源指纹及导入标识；重复执行可识别已导入内容，失败可恢复，保留 OpenClaw 原始文件与 Namo 既有数据。
- [ ] 将“导入完成”和“机器人已切换”分成两个阶段。用户明确确认具体应用后，先处理在途任务，停止或禁用来源中该应用的接收入口，再启动 Namo；无法可靠自动控制来源服务时，给出精确手动步骤并核对结果。不能启动同一应用的第二个接收端，也不能顺带停掉其他机器人或渠道。
- [ ] 切换后验证 Namo 连接、实际飞书收发、消息归属及单一接收端；给出迁移报告与回退入口。切换窗口可能漏收的消息需明确说明，不承诺平台会自动补发；回退先停止 Namo 接收，再恢复原接收端，保留切换期间产生的新数据，不盲目重放任务或覆盖数据库。

切换确认必须明确展示所选应用和以下提醒：

> 确认切换后，这个飞书机器人将由 Namo 接收消息并调用已配置的 Agent 处理，OpenClaw 将不再处理该机器人的新消息。机器人应用保持不变，但命令、能力和权限按 Namo 的配置生效。未迁移或尚未生效的记忆与功能已在清单中列出。切换期间可能短暂无法响应；请确认后再接管。

验收标准：覆盖已有 / 全新 Namo 配置、多 OpenClaw 实例、多应用、来源格式不支持、缺失凭据、配置冲突、重复导入、导入中断和回退；密钥不进入输出或日志；身份与记忆范围不串用；未确认切换时不修改来源服务；接管后真实消息只由 Namo 处理，用户确认收到回复。没有完成收发验证时只能报告已导入或已启动，不能报告迁移验收成功。
