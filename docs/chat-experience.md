# 飞书日常回复

schema 7 已上线简洁回复与独立 runner。schema 8 候选进一步接入持久化受理表情、原消息 / 话题路由、安全富文本和一张可更新的进度卡片；当前在线仍是 schema 7，新交互尚未随服务发布。

## 默认看到什么

- 消息在身份、触发和持久化通过后，独立记录一次受理表情；快速完成不会补发过时反馈，未授权消息不回应。
- 普通无格式回答直接发文字；安全 Markdown 子集使用富文本展示，原始模型答复仍保留在持久记录中。
- 接收后超过可配置延迟（默认 12 秒）才发送进度卡片；阶段变化更新同一张卡片，更新最短间隔默认 5 秒，无新阶段的状态确认默认 30 秒。最终答复保持独立。
- 有执行操作的结果以答复为主。卡片保留项目名称、详情入口，以及文件补丁、检查命令正常退出、操作失败或待核对等必要摘要。
- 默认不展示任务编号、工作线、输入版本、PID、完整命令记录或原始状态 JSON。模型自己的答复正文不会被截删或重写。
- 点击“查看详情”或发送 `/task`，查看本人在当前话题最近任务的可读说明；`/task N-编号` 指定任务。详情显示执行与投递状态、有限执行记录及任务编号，不调用模型。`/tasks` 列出本人任务，`/status` 显示项目和排队情况。

普通回答和执行结果的展示依据已保存的执行事件与任务状态，不按 `ping`、问候语等关键词绕过任务处理。问答也保留原来的持久化、去重、项目与会话规则；较慢的问答同样会收到处理提示。

正常退出只说明检查命令的退出结果，不等于功能验收通过。失败、记录不完整、发送结果不明及未确认应用的补充要求仍会明确提示。平台接受与用户已读继续分别处理。

## 进度、路由与恢复

入站、任务、路由和延迟提示在同一接收事务中保存。延迟提示使用 `deferred` 状态和本机接收时间；到期仍在排队或执行时才进入发送队列，重启不会重新计时或重复创建。回复目标在接收时固定为原消息 / 话题上下文，不在发送时从正文推断。

任务完成、取消或独立运行已结束 / 失联时，尚未发送的提示标记为 `suppressed`。已发送进度卡片由单一版本写者更新；阶段合并、旧版本和终态栅栏防止旧进度覆盖完成 / 失败 / 取消。已经开始发送、已被平台接受或结果不明的操作保留原状态，不能假装撤回，也不自动重发。

结果内容与发送格式在出站流程中固定；安全富文本只转换展示副本，不把模型正文当作卡片 JSON，不生成 `at` / 图片标签。明确格式拒绝才允许文字兜底。历史答复和执行证据不改写；表情与进度设置不扩大执行权限。

## 验证范围

隔离测试覆盖单条文字、安全富文本分块、原消息 / 话题路由、表情去重、慢任务阶段、更新合并、终态竞争、排队、取消、未知发送不重试、重启恢复、卡片归属和证据保留。schema 7 的真实飞书 `ping` 已确认只收到简短回答；schema 8 的表情、话题、Markdown、进度更新和设置开关尚待发布后在桌面 / 移动端验收。最终完整测试数量由发布复审统一核定。

## 2026-10-26 反馈调研与 schema 8 实现

以下范围根据用户截图和飞书官方接口整理，并已在 schema 8 源码候选实现；尚未在线发布或完成真实客户端验收。截图只用于定位展示现象，没有据此读取其中的 PR 或推断模型执行是否正确。

### 原因与证据

| 现象 | 当前代码证据 | 结论 |
| --- | --- | --- |
| 收到消息后没有即时回应 | schema 8 在持久接受后通过 `Feedback` 记录并添加受理表情，快速完成抑制过时反馈 | 源码已修正；真实权限、时延和客户端可见性待验收 |
| “正在处理”长时间不变 | 持久 `run_activity` 驱动一张版本化进度卡片，更新节流、心跳说明和终态栅栏分离 | 源码已修正；不展示思考过程，也不编造百分比 |
| Markdown 原样显示 | `richtext` 只转换安全子集并按语法边界分块；普通无格式短答继续使用文字 | 源码已修正；复杂语法会明确降级，真实渲染待验收 |
| 长内容和话题关联 | 出站路由在接收时固定，支持原消息 / 话题；长内容按展示结构分块而不是只按字符硬切 | 源码已修正；群话题与异常降级仍需真实验收 |

### 官方能力与实现选择

- **表情确认**：使用 [添加消息表情回复](https://open.feishu.cn/document/server-docs/im-v1/message-reaction/create)，对已接受的原消息操作，机器人须在会话内；最小权限可选 `im:message.reactions:write_only`。保存返回的 reaction ID，后续只清理本机器人添加的记录，不通过模型发送。无需为了添加表情而订阅所有用户的表情事件。
- **阶段卡片更新**：使用 [更新已发送的消息卡片](https://open.feishu.cn/document/server-docs/im-v1/message-card/patch)。该接口要求发送与更新身份一致、更新前后均配置 `update_multi: true`；当前文档限制为 14 天内卡片、单消息 5 QPS。权限支持 `im:message`、`im:message:send_as_bot` 或 `im:message:update` 中任一项，不能一概要求新增全部权限。现有卡片未声明共享更新，首版只更新新流程创建的进度卡片。
- **正文格式**：飞书 [富文本 Markdown 组件](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/card-components/content-components/rich-text) 使用 `tag: markdown`，与 `plain_text` 不同；旧版 `lark_md` 文本组件支持范围也不同。标题、引用、表格等需核对 JSON 2.0 组件能力，不能直接把 GitHub Markdown 当作完全兼容的输入。首版先支持经过验证的基础子集，复杂格式降级，不把全量卡片 2.0 迁移作为三个问题的共同前置条件。
- **话题回复**：使用 [回复消息](https://open.feishu.cn/document/server-docs/im-v1/message/reply) 的原消息 ID 和 `reply_in_thread`，已有话题内消息默认沿话题回复；普通群是否新建话题须有明确产品规则。保留回复去重标识，不因话题不存在或回复结果不明静默改投主群。

官方页面正文通过对应 `.md` 文档核对；未调用真实飞书写接口，未验证当前应用的表情权限或客户端渲染。此处不声称已审计 OpenClaw 的具体实现。

### 开发范围与顺序

#### 第一批：即时确认、原话题回复、Markdown 正确展示（schema 8 已实现）

- [x] 在身份和触发规则通过、消息及任务持久化成功后，独立排入表情回应；不能在落库前表示已接单。
- [x] 表情操作去重并记账；快速完成抑制过时反馈，结束后清理，结果不明不盲重试，也不阻塞任务或导致模型重跑。
- [x] 出站目的地保存聊天、原消息和话题上下文；表情、阶段通知与结果沿用固定路由，不扩大群消息触发范围。
- [x] 安全 Markdown 渲染层支持基础子集；普通无格式短答继续使用文字，复杂格式明确降级。
- [x] 原始答复保留，只转换展示副本并按语法节点分块，保护链接和代码围栏。
- [x] 模型正文不能成为卡片 JSON、人员标签、全员提及或自动图片抓取；格式拒绝才降级，未知发送不补发第二份结果。

#### 第二批：有依据的阶段进度与时间更新（schema 8 已实现）

- [x] 慢任务才展示进度卡片，默认 12 秒且可配置；长任务更新同一张卡片，最终答复独立，终态移除停止入口。
- [x] 从持久化任务、runner 和工具事件投影有限阶段；不能可靠分类时使用保守文案，不根据计时器编造进展。
- [x] 区分开始、活动和状态确认时间；心跳不冒充工具进展，失联显示待核对。
- [x] 阶段更新合并并节流，默认最短 5 秒、状态确认 30 秒；不显示百分比、预计时间、思考过程或原始工具日志。
- [x] 表情与卡片更新保存操作记录、平台标识和版本；单写者、终态栅栏和按钮绑定阻止旧进度覆盖终态。
- [x] 更新失败不重跑执行器或阻塞最终结果；重启只恢复必要最新状态。工作台提供表情、进度开关和频率设置。

### 验收清单

- [ ] 快任务即时确认且没有多余进度卡片；重复事件只有一次受理和一次表情操作；未授权或未触发的消息无任何回应。
- [ ] 排队任务不会被显示为已开始执行；长任务阶段来自真实事件，时间含义明确；等待用户、取消、超时和失联不继续显示正常运行。
- [ ] 同一群中两个话题并行测试，表情、卡片、最终结果和按钮均归属正确；撤回原消息、话题不可用时不越范围投递。
- [ ] 更新限流、乱序、超时、终态竞争、接收服务重启和 runner 存活分别测试；不会刷屏、旧版本覆盖终态、双发最终结果或重复调用模型。
- [ ] 以截图同类的 PR 分析文本验证粗体、长链接、下划线、反引号、列表和代码块；覆盖超过 2,000 字、超长单链接、表格降级、HTML / at 标签及非法 URL。平台返回成功不能代替桌面端和移动端实际渲染验收。
- [ ] 在授权的真实飞书私聊和群话题完成表情、阶段卡片、时间更新及 Markdown 收件确认；截图和记录脱敏，不将用户原始截图或私人 PR 内容提交到公开仓库。
