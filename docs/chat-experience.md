# 飞书日常回复

本批精简聊天展示，保留任务、运行和投递记录。2026-10-26 已切换既有在线实例，与独立 runner 一同上线。

## 默认看到什么

- 普通回答直接发文字。例如 `ping` 的答复可以只是 `pong，在。`。没有执行事件且正常完成时，不附加结果卡片。
- 接收后等待 12 秒仍未结束，才发送一次简短的排队或处理提示。启用卡片时提供查看详情和停止入口；未启用卡片时发送相同的简短文字。
- 有执行操作的结果以答复为主。卡片保留项目名称、详情入口，以及文件补丁、检查命令正常退出、操作失败或待核对等必要摘要。
- 默认不展示任务编号、工作线、输入版本、PID、完整命令记录或原始状态 JSON。模型自己的答复正文不会被截删或重写。
- 点击“查看详情”或发送 `/task`，查看本人在当前话题最近任务的可读说明；`/task N-编号` 指定任务。详情显示执行与投递状态、有限执行记录及任务编号，不调用模型。`/tasks` 列出本人任务，`/status` 显示项目和排队情况。

普通回答和执行结果的展示依据已保存的执行事件与任务状态，不按 `ping`、问候语等关键词绕过任务处理。问答也保留原来的持久化、去重、项目与会话规则；较慢的问答同样会收到处理提示。

正常退出只说明检查命令的退出结果，不等于功能验收通过。失败、记录不完整、发送结果不明及未确认应用的补充要求仍会明确提示。平台接受与用户已读继续分别处理。

## 进度提示与恢复

入站、任务和延迟提示在同一接收事务中保存。延迟提示使用 `deferred` 状态和本机接收时记录的时间；到期仍在排队或执行时才进入发送队列，重启不会重新计时或重复创建。

任务完成、取消或独立运行已结束 / 失联时，尚未发送的提示标记为 `suppressed`，保留记录但不再发出。已经开始发送、已被平台接受或结果不明的提示保留原状态，不能假装撤回，也不自动重发。卡片仍为独立消息，不做流式更新；提示可能在发送途中与任务完成交错，但不能覆盖最终结果。

结果内容与发送格式在原有出站流程中固定；明确的卡片格式拒绝才允许文字兜底。仅精简新消息的默认展示，不改写历史已保存的答复、卡片或执行证据。没有新增数据库表或扩大执行权限。

## 验证范围

隔离测试覆盖普通回答单条文字、慢任务提示、排队、取消、完成与待发送提示交错、未知发送不重试、卡片详情归属、命令查询和证据保留。独立 runner 的离线完成 / 重连场景同时验证不会补发过时提示。本批 131 项测试通过。授权切换后，真实飞书 `ping` 验收确认只收到简短回答：进度记录为 suppressed，结果为已发送文字；新版执行卡片、真实停止按钮等仍需分别验收。

## 2026-10-26 反馈调研与待开发修正

以下根据用户提供的三张截图、当前工作区源码和飞书官方接口文档整理，仅为调查结论与开发范围，尚未实现或在线验收。截图用于定位展示现象，没有据此读取其中的 PR 或推断模型执行是否正确。

### 原因与证据

| 现象 | 当前代码证据 | 结论 |
| --- | --- | --- |
| 收到消息后没有即时回应 | `src/tasks.ts` 的 `PROGRESS_DELAY_MS` 为 12 秒；`progress()` 只激活一次延迟通知。`src/feishu.ts` 没有表情回复接口 | 是反馈机制缺失，不能仅凭截图归因为模型慢或收不到消息 |
| “正在处理”长时间不变 | 进度内容是固定文案，已发送卡片不更新；`src/runner-worker.ts` 更新运行心跳并保存执行证据，但未投影为用户进度；`src/runtime.ts` 不转发 commentary | 执行事件与用户展示之间缺少进度模型，不能用不断刷新时间假装取得新进展 |
| Markdown 原样显示 | `src/cards.ts` 将正文放入 `div.text` 的 `plain_text`；普通答复经 `src/feishu.ts` 发送为 `text`；现有卡片测试也明确要求纯文本 | 属于 Namo 当前输出格式选择，不是飞书完全不支持 Markdown；截图中的粗体、链接和反引号原样展示与此一致 |
| 长内容和话题关联的附加问题 | `src/store.ts` 每 2,000 个 Unicode 字符硬切分；出站只调用 `message.create` 向 `chat_id` 发送，未使用 `message.reply` | 切片可能破坏链接、代码围栏和列表；入站按话题隔离并不等于出站会回到话题。前者是代码推导出的风险，不能认定截图里每个换行都由切片导致 |

### 官方能力与实现选择

- **表情确认**：使用 [添加消息表情回复](https://open.feishu.cn/document/server-docs/im-v1/message-reaction/create)，对已接受的原消息操作，机器人须在会话内；最小权限可选 `im:message.reactions:write_only`。保存返回的 reaction ID，后续只清理本机器人添加的记录，不通过模型发送。无需为了添加表情而订阅所有用户的表情事件。
- **阶段卡片更新**：使用 [更新已发送的消息卡片](https://open.feishu.cn/document/server-docs/im-v1/message-card/patch)。该接口要求发送与更新身份一致、更新前后均配置 `update_multi: true`；当前文档限制为 14 天内卡片、单消息 5 QPS。权限支持 `im:message`、`im:message:send_as_bot` 或 `im:message:update` 中任一项，不能一概要求新增全部权限。现有卡片未声明共享更新，首版只更新新流程创建的进度卡片。
- **正文格式**：飞书 [富文本 Markdown 组件](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/card-components/content-components/rich-text) 使用 `tag: markdown`，与 `plain_text` 不同；旧版 `lark_md` 文本组件支持范围也不同。标题、引用、表格等需核对 JSON 2.0 组件能力，不能直接把 GitHub Markdown 当作完全兼容的输入。首版先支持经过验证的基础子集，复杂格式降级，不把全量卡片 2.0 迁移作为三个问题的共同前置条件。
- **话题回复**：使用 [回复消息](https://open.feishu.cn/document/server-docs/im-v1/message/reply) 的原消息 ID 和 `reply_in_thread`，已有话题内消息默认沿话题回复；普通群是否新建话题须有明确产品规则。保留回复去重标识，不因话题不存在或回复结果不明静默改投主群。

官方页面正文通过对应 `.md` 文档核对；未调用真实飞书写接口，未验证当前应用的表情权限或客户端渲染。此处不声称已审计 OpenClaw 的具体实现。

### 开发范围与顺序

#### 第一批：即时确认、原话题回复、Markdown 正确展示

- [ ] 在身份和触发规则通过、消息及任务持久化成功后，独立排入表情回应；目标为健康服务正常网络下收到事件后约 1–2 秒可见，记录事件接收、入库和 API 回执时间分别衡量。不能等到模型开始才确认，不能在落库前表示已接单。
- [ ] 选定并验证一个官方支持的“收到 / 处理中”表情，明确排队不代表执行已开始；重复事件不重复添加，不定时反复添加表情。快速完成不补发过时的处理中表情；正常结束、失败、取消后清理，并处理重启、撤回消息、权限不足和 API 结果不明。降级为一次简短确认时也要去重，不能阻塞任务执行或导致模型重跑。
- [ ] 将出站目的地扩展为聊天、原消息和话题上下文，创建通知时固定路由，表情、阶段通知与结果保持一致；覆盖私聊、普通群 @、群内话题和话题群，不扩大既有群消息触发范围。
- [ ] 建立统一的安全 Markdown 渲染层，基础支持粗体、链接、列表、行内代码和代码块。标题、引用、表格和图片按选定卡片版本转换或明确降级；普通无格式短答继续使用文字，有格式答复走富文本，不能继续把 Markdown 塞进纯文本消息。
- [ ] 原始答复保留；仅对展示副本作语法转换、链接校验和分块。以段落 / 语法节点切分，处理超长单段和代码块，保持链接完整、围栏闭合；按实际载荷字节与平台限制验收，替换只按字符硬切的假设。
- [ ] 不将模型正文当作卡片 JSON；转义不受信任的原生标签、人员标签和全员提及，链接默认仅允许 HTTP(S)，本地路径以文本显示，图片不自动抓取上传。格式明确拒绝时才降级为可读文本；发送结果不明先核对，不再发一份结果。

#### 第二批：有依据的阶段进度与时间更新

- [ ] 保留慢任务才展示进度卡片的原则，默认 12 秒阈值可配置；短任务用表情加最终答复，避免多张通知。长任务更新同一张进度卡片，最终答复保持独立且不可变；任务结束将旧进度卡片改为终态并移除停止入口，避免长期残留“正在处理”。这是对当前“不更新已发送卡片”策略的受控扩展，不是逐 token 流式输出。
- [ ] 从持久化任务、runner 和工具事件投影排队、执行中、工具执行、等待用户、整理结果及终态。工具阶段可显示经过脱敏和验证的“运行检查”等摘要；无法可靠分类时仅展示“正在执行工具”，不根据计时器编造“正在测试 / 即将完成”。
- [ ] 展示开始时间、已耗时、最近活动时间和最近状态确认时间，明确时区；区分 worker 心跳、Agent / 工具新事件和卡片刷新，三者不能混为任务进展。没有新事件但 worker 存活时说明“执行进程仍在线，暂无新进展”；心跳过期或失联显示状态待核对，不持续制造活跃假象。
- [ ] 阶段变化触发更新并合并高频事件，默认最多每 5 秒一次；长时间无阶段变化可每 30 秒刷新状态确认时间，参数以验收和平台配额调整。等待用户时停止无意义心跳通知；首版不生成完成百分比或预计剩余时间，不调用额外模型编写进度，不展示思考过程或原始工具日志。
- [ ] 为表情和卡片更新保存操作记录、平台标识、展示版本及发送结果；每张卡片只有一个更新写者，串行发送并合并待发版本。终态取消未发送的旧更新；已在途、超时或结果不明的更新须核对后收敛，不能使终态卡片被旧进度覆盖。按钮校验仍绑定用户、消息、任务、输入版本与有效期。
- [ ] 更新失败不重跑执行器、不阻塞最终结果；明确失败可有界重试并遵守退避，结果不明先核对。若无法确认进度卡片已收尾，在最终回复说明以最终结果为准；重启只恢复必要最新状态，不补发全部历史阶段。补齐 `doctor` / 初始化权限提示及 UI 的表情、进度开关和刷新频率设置。

### 验收清单

- [ ] 快任务即时确认且没有多余进度卡片；重复事件只有一次受理和一次表情操作；未授权或未触发的消息无任何回应。
- [ ] 排队任务不会被显示为已开始执行；长任务阶段来自真实事件，时间含义明确；等待用户、取消、超时和失联不继续显示正常运行。
- [ ] 同一群中两个话题并行测试，表情、卡片、最终结果和按钮均归属正确；撤回原消息、话题不可用时不越范围投递。
- [ ] 更新限流、乱序、超时、终态竞争、接收服务重启和 runner 存活分别测试；不会刷屏、旧版本覆盖终态、双发最终结果或重复调用模型。
- [ ] 以截图同类的 PR 分析文本验证粗体、长链接、下划线、反引号、列表和代码块；覆盖超过 2,000 字、超长单链接、表格降级、HTML / at 标签及非法 URL。平台返回成功不能代替桌面端和移动端实际渲染验收。
- [ ] 在授权的真实飞书私聊和群话题完成表情、阶段卡片、时间更新及 Markdown 收件确认；截图和记录脱敏，不将用户原始截图或私人 PR 内容提交到公开仓库。
