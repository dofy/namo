# 飞书日常回复

源码已接入持久化受理表情、原消息 / 话题路由、安全富文本及可更新进度卡片。历史发布见[交付台账](archive/roadmap-delivery.md)；真实客户端展示仍需逐项验收。

## 默认看到什么

- 消息在身份、触发和持久化通过后，独立记录一次受理表情；快速完成不会补发过时反馈，未授权消息不回应。
- 普通无格式回答直接发文字；安全 Markdown 子集使用富文本展示，原始模型答复仍保留在持久记录中。
- 接收后超过可配置延迟（默认 12 秒）才发送进度卡片；阶段变化更新同一张卡片，更新最短间隔默认 5 秒，无新阶段的状态确认默认 30 秒。最终答复保持独立。
- 有执行操作的结果以答复为主。卡片保留项目名称、详情入口，以及文件补丁、检查命令正常退出、操作失败或待核对等必要摘要。
- 默认不展示任务编号、工作线、输入版本、PID、完整命令记录或原始状态 JSON。模型自己的答复正文不会被截删或重写。
- 点击“查看详情”或发送 `/task`，查看本人在当前话题最近任务的可读说明；`/task N-编号` 指定任务。详情显示执行与投递状态、有限执行记录及任务编号，不调用模型。`/tasks` 列出本人任务，`/status` 显示项目和排队情况。

普通回答和执行结果的展示依据已保存的执行事件与任务状态，不按 `ping`、问候语等关键词绕过任务处理。问答也保留原来的持久化、去重、项目与会话规则；较慢的问答同样会收到处理提示。

正常退出只说明检查命令的退出结果，不等于功能验收通过。失败、记录不完整、发送结果不明及未确认应用的补充要求仍会明确提示。平台接受与用户已读继续分别处理。

## 进度、路由与恢复

入站、任务、路由和延迟提示在同一接收事务中保存。延迟提示使用 `deferred` 状态和本机接收时间；到期仍在排队或执行时才进入发送队列，重启不会重新计时或重复创建。回复目标在接收时固定为原消息 / 话题上下文，不在发送时从正文推断。

任务完成、取消或独立运行已结束 / 失联时，尚未发送的提示标记为 `suppressed`。已发送进度卡片由单一版本写者更新；阶段合并、旧版本和终态栅栏防止旧进度覆盖完成 / 失败 / 取消。已经开始发送、已被平台接受或结果不明的操作保留原状态，不能假装撤回，也不自动重发。

结果内容与发送格式在出站流程中固定；安全富文本只转换展示副本，不把模型正文当作卡片 JSON，不生成 `at` / 图片标签。明确格式拒绝才允许文字兜底。历史答复和执行证据不改写；表情与进度设置不扩大执行权限。

## 验证范围

隔离测试覆盖单条文字、安全富文本分块、原消息 / 话题路由、表情去重、慢任务阶段、更新合并、终态竞争、排队、取消、未知发送不重试、重启恢复、卡片归属和证据保留。schema 7 的真实飞书 `ping` 已确认只收到简短回答；schema 8 已获当前客户端的进度计时和 Markdown 固定样例确认。表情、群话题、设置开关及桌面 / 移动端覆盖仍需分项验收。最终完整测试数量由发布复审统一核定。

## 格式与验收限制

安全子集转换不等于完整 GitHub Markdown 支持。表格等复杂格式可能降级；普通正文、结果卡片和不同客户端的显示应分别验证。已修复普通成功回复被纯文本缓存、重启预备路径丢失富文本，以及结果卡片使用不适合代码块的内容组件。标题、引用和表格在旧卡片协议中明确降级。2026-10-27 普通回复和结果卡片的固定格式样例已获真实客户端确认；其他内容和客户端仍需分别核对。

实现入口为 `src/richtext.ts`、`src/engine.ts`、`src/feedback.ts` 与 `src/feishu.ts`。进度更新不是模型逐 token 流式输出；状态确认不能冒充工具进展。
