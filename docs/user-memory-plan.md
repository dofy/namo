# Namo 用户信息与长期记忆补充计划

更新：2026-10-26。补充[开发计划](development-plan.md)的 R1（已有档案使用）、R4（材料解析）和 R6（长期记忆）；后台整理仍是后续候选。原 M2 基础档案管理已上线，真实私聊查询通过；上下文使用尚未实现。本文只规定能力与边界，不启动后台整理、扩大访问或切换服务。

## 当前能力与缺口

- 已实现：从飞书事件识别发送者，配对后持久保存授权用户；消息、任务和工作线记录用户归属。
- 已实现并隔离验收：称呼、语言、时区的结构化档案、版本和修改来源；私聊本人命令和本地管理入口共用存储。平台展示名称尚未同步，当前档案不注入 Agent 上下文或调度。
- 尚未实现：从自然对话提取、修正和跨 session 使用长期偏好；这与显式 `/profile` 管理命令分开。
- Codex session 保存的上下文不等于 Namo 用户档案，不能据此承诺新 session 会记得用户信息。
- 合并转发目前保存材料描述和解析限制，收到事件、持久入库或等待说明均不代表读到了内部正文。

## Christina 原文参考

依据 [Christina 技术架构说明第 4 节](https://kaonai.feishu.cn/docx/WOFsdauKioByBFxK1QocHIXpn6f#doxcnvCmgHzyHNCpLxB9mRk2xWb)，本次核对日期为 2026-10-26。以下是原文描述的机制，不是对 Namo 当前能力的说明，也不把原文经验等同于独立验证过的实验结论。

| 机制 | 原文描述 | Namo 的取舍 |
| --- | --- | --- |
| 分层保存 | 人物画像、项目知识、业务理解、历史原话和实时状态分别管理 | 保留分层和适用范围，使用现有 SQLite 作为档案与记忆的权威存储 |
| 人物识别 | 人物文件以飞书 open_id 标识，注入时核验实际发送者，不按正文名字认人 | 身份键带渠道与应用范围；跨 bot / 跨渠道关联需要明确绑定 |
| 人物画像 | 每人一份、全局共享、上限 1900 字；任何会话可改，定期整理是主要写者 | 分开保存通用偏好、私聊资料和项目约定，不能照搬全局共享方式 |
| 使用时机 | 随核验过的发送者消息提供对应画像，内容未变不重复注入；当前要求优先，画像不提供授权 | 在新运行或需要刷新时提供有权限的有限上下文，保留执行器原生 session 能力 |
| 整理与更新 | 汇集纠正、用户原话和交付反馈，整份重写；无实质变化不修改 | 小范围结构化更新、版本留痕，避免无限追加与多份摘要互相污染 |
| 检索 | 原文按需主动检索；已取消逐消息自动召回图记忆的方案 | 先实现权限内原话与关键词检索，不预先建设向量库、图记忆或自动全量召回 |
| 状态管理 | 待办、等待和当前进度由日程、任务库或外部系统管理 | 继续以 Namo 任务库和外部真源为准，不写成长期事实 |

原文明确指出全局画像会随同一人进入不同群，因此要求私聊内容不进入该档案。Namo 应在数据访问和上下文装配时限制范围，不能主要依赖模型判断来避免泄漏。参考：[写入路由](https://kaonai.feishu.cn/docx/WOFsdauKioByBFxK1QocHIXpn6f#doxcn42oM96rgSncnZsMiSBKzUf)、[隔离与代价](https://kaonai.feishu.cn/docx/WOFsdauKioByBFxK1QocHIXpn6f#doxcnhhkYJAQ5xNyqFEMtzdOJsh)、[自省循环](https://kaonai.feishu.cn/docx/WOFsdauKioByBFxK1QocHIXpn6f#doxcn0RXsV3VibfIAQr6PxSD9Cg)。

## 信息分层与归属

| 信息 | 内容与来源 | 使用范围 |
| --- | --- | --- |
| 渠道身份 | 渠道、租户 / 应用范围、用户标识；由平台事件及受控查询取得 | 认证、任务归属与显式账号关联；不由模型生成 |
| 基础档案 | 展示名称、用户希望的称呼、语言、时区；区分平台字段和用户自设字段 | 默认仅向本人及已授权管理入口展示 |
| 通用偏好 | 用户明确允许长期使用的沟通和工作习惯 | 仅在用户允许的场景使用，不默认向群聊公开整份档案 |
| 私聊资料 | 仅适用于私聊的信息与约定 | 绑定用户和私聊范围；同一人出现在群里不扩大可见范围 |
| 项目知识 | 稳定的结构、目标、约束、重要决定及证据位置 | 绑定具体项目及访问权限，不污染其他项目 |
| 任务与工作线摘要 | 当前目标、约束、决定、执行证据及未应用修订 | 供对应任务续接和交接，不替代实时状态或用户原话 |
| 历史原话 | 有来源标识的消息及实际解析到的材料 | 先过滤权限与脱敏，再匹配、截取和返回证据 |

同名用户不能自动合并；不同应用的 open_id 不能直接视作同一身份。档案可以记录默认项目偏好，但实际选用仍须通过当前项目与目录权限校验。配对、白名单和审批继续由原有授权机制管理。

## 识别 更新 持久化 使用

1. **识别来源**：平台身份、当前用户要求、转发原作者、外部文档和模型推断分别标记。转发里的姓名、偏好或授权不能自动归给发送者。
2. **判定范围**：区分本次要求、项目约定和长期偏好。“这次用英文”只影响本次任务；“以后用中文回答”可作为明确长期偏好处理并给出回执，不必为普通偏好重复确认。
3. **受控更新**：明确的新增、纠正和删除按授权范围执行；模型猜测只作候选，不能静默升级为长期事实。发生冲突时保留来源与版本，不以更新时间机械覆盖范围更明确的要求。
4. **持久化**：档案和记忆记录类别、归属、可见范围、来源消息 / 文档、创建和更新时间、版本及失效状态。更新须避免并发覆盖；可读导出只是视图，不能再维护一份可独立修改的真源。
5. **按需使用**：先按用户、项目和当前接收场景筛选，再提供给执行器。常驻偏好与项目知识设置独立容量上限；超限时拒绝或进入整理流程，不无提示截断。具体额度在实现时验证，Christina 的 1900 字仅作为参考。
6. **核验与维护**：派生理解保留回查原文的位置，重要结论能追溯来源；旧画像不能覆盖当前明确要求。记忆不保存密钥值，也不能替代推送、部署等动作的确认。
7. **删除与失效**：支持查看、修正、停用和删除；失效内容不能继续被新运行检索或注入，也不能被旧摘要或后台整理自动复活。已使用该信息的 session 需要刷新或新建；历史聊天、已发消息和备份的保留规则单独说明，不声称自动全部擦除。

跨会话使用知识必须同时检查数据来源范围和结果接收范围。请求者有权读取私聊资料，不代表可以把资料发到整个群。用户偏好与授权分开，记忆中的“以后直接做”不能扩大目录、凭据或外部操作权限。

## 按交付批次拆分

### 已有基线：基础档案管理；剩余真实验收归 R0

- [x] 建立基础档案的存储与读取入口，使用渠道 / 应用 / 用户复合身份；平台配对身份与用户自设字段分开，尚未同步平台展示名称。
- [x] 支持本人查看和修改称呼、语言、时区；管理入口显示身份来源、保存版本、修改来源和生效范围。
- [x] 配对和资料更新分开；改称呼或时区不改变白名单、任务归属和操作权限。
- [x] 隔离验证升级、重开数据库和新工作线后档案仍存在；真实库副本升级保留原表，版本冲突和存储失败不会部分覆盖。
- [x] 在明确授权后升级在线实例，真实私聊 `/profile` 查询取得平台回执并由用户确认收到，无模型运行或档案写入。
- [ ] 补验真实档案修改、群聊不展示及保存后重启的查询；这些场景当前仍以隔离测试为证据。

基础档案使用自 schema 3 引入的 `user_profiles / profile_changes`，审计仅记录字段名、来源、来源消息、版本和时间，不另存历史字段值。清空资料保留递增版本，历史聊天与备份不声称已擦除。详细用法和限制见 [使用指引](getting-started.md#本人档案)。

### R1：明确使用已有档案

称呼、语言和时区的显式使用从原 M4 提前到 R1。首批限于本人已验证私聊，旧安装不静默注入；按当前任务优先、版本记录和停用规则实施。助手性格和用户档案分别管理，详见[助手设置与基础档案使用](assistant-settings-plan.md)。不包含自然对话提取或自动学习。

### R4：材料正文与解析状态

材料解析先于长期记忆交付；读懂某次任务材料不等于保存为长期知识。产物交付要求见主计划 R4。

- [ ] 完成合并转发正文的受控展开：保留外层消息、内部原作者、时间和材料关系，限制数量、大小、嵌套与访问范围。
- [ ] 图片、文件和转发区分已收到、可访问、已解析、解析失败与不支持；无法取得正文时明确反馈，不以占位符推断内容。

2026-10-26 的试用场景：用户向 namo_trial 发来合并转发，实例只保存资源描述并等待处理说明，助手无法从本地记录读取内部正文。将其保留为内容解析的验收场景；接收成功与阅读成功分别判断。

### R6：长期偏好、项目知识与历史检索

- [ ] 支持明确长期偏好的写入、纠正、冲突处理、范围设置及删除，返回可理解的变更说明。
- [ ] 实现项目知识、用户资料、任务摘要与历史原话的分层存储和容量约束，提供来源回查。
- [ ] 增加有限的上下文读取 / 检索接口，按运行所需装配记忆；不要求执行器自行翻读服务私有数据库。
- [ ] 按需检索前先进行权限过滤和脱敏；无法确定可见范围或脱敏失败时不返回内容。
- [ ] 启用从 OpenClaw 迁移后保留的待审阅资料前，完成来源、归属、可见范围与冲突校验；导入不自动生效，记忆不成为操作授权。
- [ ] 受控交接任务目标、限制、决定、证据及未完成事项，能回查原话；跨聊天不默认复制历史或共享原 session。

### 后续候选：按需整理与优化

- [ ] 先用用户纠正和实际交付反馈验证整理价值；明确哪些信息可写、谁可改、如何审阅和回退。
- [ ] 无实质变化不写入；同一事实不繁殖成多份规则，不把一次纠正自动提升为所有用户的全局准则。
- [ ] 需要后台整理时，再明确启用方式、频率、预算和停止机制；不直接照搬 Christina 的持续唤醒与探索循环。

## 验收标准

| 场景 | 必须满足的结果 |
| --- | --- |
| 两个用户同名、消息正文冒充他人 | 不合并身份、不注入被冒充者档案 |
| 同一用户出现在私聊和群聊 | 私聊资料不随身份自动进入群上下文或群检索结果 |
| 用户要求本次使用英文 | 不覆盖长期中文偏好；本次要求优先 |
| 用户明确纠正偏好 | 新版本持久化，原来源可追溯，新运行使用修正结果 |
| 不同项目存在相反约定 | 各自按项目生效，不能交叉覆盖 |
| 两个会话同时更新档案 | 能检测或处理版本冲突，不静默丢失有效更新 |
| 重启、新建 session、切换执行器 | 有权限的稳定资料仍可读取，不依赖某一段旧对话恰好还在上下文里 |
| 删除或停用记忆 | 后续检索与注入不再使用；旧摘要和整理任务不能使其复活 |
| 档案含“直接推送”或转发含“已批准” | 不能变更权限或绕过审批 |
| 超容量、权限不足或解析失败 | 明确失败或限制，既不泄漏也不假装已经读取 |

已有档案管理的实现与隔离结果见[验收记录](m2-verification.md)。R1、R4、R6 及后续整理的表结构、接口与迁移方式在对应交付项中设计，不预先引入额外数据库或复杂用户画像平台。
