# Namo 技术指南

[English](technical-guide.md) · [产品介绍](../README.zh-CN.md)

本指南介绍安装、功能、运维与执行边界。模块实现和日常维护的更多细节分别见[技术实现](architecture.md)和[运维指南](operations.md)。

## 已有能力

- **飞书 / Lark 入口**：长连接、私聊、群 @、文字与基本富文本；按组织身份或指定成员名单接入。
- **组织接入**：从飞书应用检测组织身份，成员无需逐人配对；所有准入成员共享白名单目录和已授权 MCP，任务默认在独立会话目录运行。
- **群聊 PR 审查**：通过服务端 GitHub 连接读取固定 base/head 的有界补丁，在获授权会话中回复发现和覆盖限制，不自动发布 GitHub 评论。
- **目录与会话**：白名单目录统一可读写，对话产物使用独立工作目录，支持带历史摘要刷新会话。
- **持久化任务**：SQLite 入站与出站、消息去重、输入修订、同聊天及重叠可写目录串行，以及全局并发限制。
- **提问与回答**：Agent 可暂停等待补充；引用问题回复，或点击与问题对应的选项按钮后继续。
- **独立运行进程**：任务与接收服务分别运行；中断或结果不明时保留记录供核对，不盲目重跑。
- **执行证据**：文件补丁、命令退出码、产物检查和 Git HEAD 快照，并明确采集范围与限制。
- **助手与范围记忆**：可选启用的助手身份和风格，带来源、范围及隐私控制的自动长期记忆，显式纠正、停用、删除及有界交接。记忆不提供操作授权。
- **材料与产物**：有界读取合并转发文字和直接发送的 UTF-8 文本文件；经授权交付指定任务文件。直接发送的 PNG/JPEG 图片会以有界、不可变的图片输入交给 Codex。
- **本地工作台**：Dashboard、任务和会话搜索、用户 / 状态 / 日期筛选、分页、详情、用户档案、助手设置、迁移记忆审阅、配置与连接诊断。
- **简洁聊天回复**：持久化受理表情、原消息 / 话题回复、安全富文本和一张可更新的进度卡片。按钮需配置飞书回调。
- **受控继续执行**：固定 HEAD 的 GitHub 检查（公开仓库或显式配置的私有仓库）可在不让模型轮询的情况下恢复原任务；Git push 按请求直接执行，记录确切任务、提交、远端和分支。
- **远程 MCP**：显式授权公网 HTTPS 连接；按外部账号实际权限直接执行请求的读写操作，无需逐次确认，支持 OAuth 或 Bearer 授权。
- **本地服务管理**：引导式初始化、独立的官方 Codex 登录、诊断、不可变发布目录与 macOS 后台服务命令。

工作台与 CLI 支持**英文、简体中文**，默认跟随系统语言，无法匹配时回退英文。任务内容、用户输入和执行日志保留原文。

PDF / Office / 音视频材料解析、自主派工和离线消息补拉仍不支持。定时提醒与任务可在飞书私聊发送 `/schedule` 管理，也可在本地工作台查看列表。已实现能力与待验收项见[开发路线图](development-plan.md)，当前服务版本从工作台核对。

## 安装与初始化

需要 **Node.js 24.15+**、官方 Codex CLI，以及已启用机器人能力的飞书或 Lark 企业自建应用。使用官方 Codex 认证和服务入口。

npm 发布前，使用 **pnpm 12.15.0** 从源码构建：

```sh
git clone https://github.com/dofy/namo.git
cd namo
pnpm install --frozen-lockfile
pnpm run build
pnpm cli init
```

可恢复的向导会引导完成 Codex 检测、独立登录、必填目录白名单、应用凭据与用户配对。真实模型和收发验证可选，可能使用账号额度。

也可构建本地 CLI 安装包：

```sh
pnpm pack
npm install -g ./namo-0.6.1.tgz
namo init
```

已有配置可通过 `--config` 指定，也支持 `NAMO_CONFIG` 和当前目录已有的 `config.local.json`。配置与数据不会被自动移动或覆盖。

```sh
namo --help
namo ui               # 本地工作台，不启动另一接收端
namo docs             # 打开本地文档；按 Ctrl+C 停止服务
namo config           # 交互式终端配置
namo login --device-auth # 无桌面环境使用官方 Codex 设备登录
```

终端菜单支持方向键、逐项编辑草稿及 Esc 放弃编辑，涵盖执行、飞书及组织准入、GitHub、MCP、助手、用户档案和 Codex 更新。Docker、持久存储与 MCP OAuth 操作见[无桌面环境](operations.md#无桌面环境)。

### 语言

在工作台侧栏底部选择 **跟随系统**、**English** 或 **简体中文**。同一浏览器与本机地址会记住选择，重新打开工作台后仍有效。切换时保留当前筛选和未保存的表单输入。

CLI 优先级为 `--lang` → `NAMO_LANG` → 系统语言（`LC_ALL`、`LC_MESSAGES`、`LANG`，最后使用运行时语言）。不支持的系统语言回退英文，`system` 可显式恢复自动选择。

```sh
namo --lang en --help
namo --lang zh-CN init
namo --lang system ui
NAMO_LANG=zh-CN namo ui
```

`--version`、路径和 JSON 输出保持可供程序读取。项目地址放在帮助信息和工作台侧栏中；外部 Agent 输出和历史记录保留原文。

### 飞书应用与服务配置

创建并发布飞书或 Lark 企业自建应用，启用机器人，并设置目标用户的应用可用范围。配置长连接，订阅 `im.message.receive_v1`；文档列出的消息权限为 `im:message.p2p_msg:readonly`、`im:message.group_at_msg:readonly` 和 `im:message:send_as_bot`，卡片按钮还需订阅 `card.action.trigger`。按向导使用一次性配对码完成用户配对；组织接入可在初始化后通过工作台配置。不要为同一个应用同时运行另一个接收端。

初始化后，如未安装后台服务，使用 `pnpm cli start` 前台运行。`pnpm cli ui` 打开本地工作台，不启动接收端；使用工作台期间需保持该终端进程运行。安装本地 CLI 包后，对应命令为 `namo start` 和 `namo ui`。

### 服务维护

macOS 上，`namo service install` 安装并启动后台服务；`start`、`stop`、`restart`、`upgrade` 和 `uninstall` 用于管理它，卸载保留配置、数据和登录。源码构建不会自行切换运行中的服务。`namo service upgrade` 会创建并校验发布快照与备份；兼容变更可在接收器在线时应用，新执行版本先试运行五分钟，在确认前接收器重启会回退。接收器、存储或依赖不兼容时，须安排停机，完成空闲检查并验证备份后升级。停止接收器不会自动停止独立 runner；停机升级前应核对任务、等待、runner 和投递状态，不能用旧备份覆盖新数据。

其他平台使用前台模式，完整平台验收尚未完成。恢复与升级细节见[运维指南](operations.md#安装升级与回退)。

## 聊天命令

常用入口：`/directories` 查看目录白名单，`/refresh` 携带有限历史摘录刷新配置，`/task` 查看任务，`/cancel` 停止任务，`/new` 开始新上下文，`/profile` 管理本人档案，私聊 `/model` 查看或设置用户默认模型，`/status` 查看服务状态和版本，`/version` 查看 Namo 与 Codex CLI 版本，`/help` 查看命令。

工作台「设置 → Codex CLI 更新」提供版本检查、手动升级、回退和自动升级开关。自动升级默认关闭；开启后由运行中的服务每天检查官方稳定版，忙碌时延后，失败后至少等待一小时再重试。Namo 将完整安装包下载到独立登录目录内的 `namo-cli/`，校验 SHA-256、CLI 版本、app-server 协议、登录、权限配置及模型目录后，空闲时原子切换；不替换全局 CLI，也不改变模型偏好。回退会关闭自动升级。当前支持 macOS/Linux 的 arm64/x64。飞书模型目录每 5 分钟刷新，CLI 切换后会重新获取；更新失败保留原版本。 历史 CLI 包暂不自动清理。


完整用法见[用自然语言与 Namo 协作](getting-started.md#用自然语言与-namo-协作)；文件交付、记忆与审批分别见[文档索引](README.md)。

## 执行边界

- 初始化必须明确填写目录白名单，目录统一开放读写；默认工作目录和数据保存在用户级 Namo 目录，不使用当前项目目录。
- 服务配置、任务数据和独立 Codex 认证文件始终排除在 Agent 可访问范围之外。不要为解决工具链路径问题而开放整个个人目录。
- Skills 仅开放已启用技能的具体目录及符号链接真实目标，权限为只读；个人 Codex 中停用的技能在 Namo 中仍保持停用。可用 `pnpm run smoke:skills` 验证实际沙箱边界，见[技能访问](architecture.md#模块与约束)。
- 写权限也允许删除文件。取消、超时或重置上下文不会撤销已发生的操作。
- Git push 记录绑定确切任务、用户 / 聊天、明确的仓库目录、预配置远端、分支、HEAD SHA、配置版本和有效期，提交请求后直接执行，无需再次批准。这是**有限保护**，不是完整强制隔离：通用联网 Agent 或其他凭据路径仍可能绕过审批入口。部署没有通用目标实现。
- OpenClaw 导入必须显式选择来源文件、受支持版本和应用；不继承模型认证、网关、插件或任务，也不会自动接管接收端。切换和回退保留为需验证的人工门槛。
- GitHub 等待默认匿名读取公开仓库。通过**连接设置 → GitHub** 配置本机 `gh` 登录或独立令牌：已准入成员在私聊和群聊中可按用户请求使用该账号实际拥有的 API 权限，不再设置逐仓库授权或逐次确认。检查等待不会自动执行写操作。见[私有 GitHub 配置](operations.md#github-连接)。
- 平台发送回执表示平台已接收消息，不代表用户已读。发送结果不明时保留记录供核对。
- 主机休眠或断网时无法持续服务；当前没有离线历史消息补拉。
- 禁止提交 `config.local.json`、`data/`、日志、令牌或认证文件。Namo 不会自动接入个人 MCP、插件或第三方模型网关。

CLI 提供 `init`、`config`、`login`、`start`、`service`、`ui`。状态、日志、诊断和 Git 推送与记录在工作台中操作；OpenClaw 来源检查在**连接设置 → 运行与维护**，实际导入使用 `namo init --import`。迁移不会自动切换接收端；推送绑定已配置目标，提交请求后直接执行。详见 [OpenClaw 迁移](operations.md#openclaw-导入)与 [Git 推送](operations.md#git-推送)。

后台服务管理当前支持 macOS；其他平台可前台运行，但尚未完成全部平台验收。当前仅接入 Codex；其他 Agent 仅保留未来插件扩展的可能性，不包含对应 SDK 或探测功能。

## 工作原理

Namo 在确认收件前先持久化入站消息，再将任务交给独立 runner。同一聊天串行执行，重叠的可写目录互斥，并受全局并发限制。官方 Codex app-server 在 Namo 的文件系统和网络策略下执行模型轮次；宿主管理的 GitHub 和 MCP 工具使用各自配置的凭据，不把凭据交给模型进程。

任务状态、等待、结果和投递记录保存在 SQLite。runner 中断或失联后不会自动重跑，投递结果不明时也不会自动重发。模型完成、平台接受消息和用户实际收到是不同的事实。当前数据库 schema 为 16；兼容的 v13–v15 数据库可迁移，不兼容旧库会被拒绝而不会自动删除。

本地工作台仅绑定 loopback，使用启动授权、HttpOnly 会话、Host / Origin 检查和内容安全策略。模块职责、剩余风险和迁移细节见[技术实现](architecture.md)。

## Ego 浏览器访问

在 macOS 上启用命令网络后，已配对用户可在私聊中使用受限的 Ego Lite 浏览器。首次使用会请求本任务授权；按键操作需要单独确认。回复 `永久允许 MA-编号` 可允许本人未来私聊任务使用当前固定操作，回复 `撤销浏览器永久授权` 可撤销。浏览器使用自身的网络权限和登录状态。群聊和定时任务不能使用此功能。

工具支持在任务专属空间中打开页面、读取快照、点击、填写以及有限的按键操作，不接受任意脚本、原始 CDP、上传或下载。永久授权不自动覆盖新增能力。正常运行结束时关闭空间；中断或结果不明时不自动重试，可能需要手动检查遗留空间。人工等待后的新运行不会恢复原浏览器空间。详见 [Ego 浏览器运维说明](operations.md#ego-浏览器原型)。

## 开发

技术栈为 TypeScript、Node.js 内置 SQLite、飞书官方 Node SDK，以及 stdio Codex app-server。工作台使用 React、Radix Themes 和 Vite，编译资源与字体随 CLI 分发。

```sh
pnpm test
pnpm run smoke:codex          # 协议握手，不进行推理
pnpm run smoke:codex -- --run # 显式真实模型测试
```

完整文档见[文档索引](README.md)，源码构建与验证见[开发指南](architecture.md#开发与验证)，待办见[后续计划](development-plan.md)。

项目地址：[github.com/dofy/namo](https://github.com/dofy/namo)。反馈问题时请提供复现步骤，勿附凭据、私有配置或原始会话数据。

组织配置：在工作台的**连接设置**中配置组织准入和 GitHub 连接。旧安装保持原范围，直到管理员明确修改。见[组织接入与权限](operations.md#配置与权限)。
