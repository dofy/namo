# 使用指南

Namo 将飞书 / Lark 聊天连接到本机官方 Codex。当前为早期版本，尚未发布 npm；后台服务管理支持 macOS，其他平台未完成完整验收。

## 安装与初始化

准备 Node.js 24.15+、pnpm 12.15.0、官方 Codex CLI，以及飞书企业自建应用。

```sh
pnpm install --frozen-lockfile
pnpm run build
pnpm cli init
```

需要安装本机命令时，运行 `pnpm pack`，再用 `npm install -g ./namo-0.2.0.tgz` 安装。源码开发方式见[技术实现](architecture.md#开发与验证)。

`init` 在交互终端中依次完成：项目及权限 → 应用凭据 → 独立 Codex 登录 → 飞书连接与用户配对 → 可选真实收发测试 → 可选后台服务。Secret 不回显，取消后可续做；已有配置和用户保留。不要同时运行同一应用的其他接收端。

飞书后台需要：

| 项目 | 配置 |
| --- | --- |
| 应用 | 企业自建应用，启用机器人，设置可用范围并发布 |
| 接收方式 | 长连接；保持初始化窗口在线后保存 |
| 消息事件 | `im.message.receive_v1` |
| 消息权限 | `im:message.p2p_msg:readonly`、`im:message.group_at_msg:readonly`、`im:message:send_as_bot` |
| 卡片按钮 | 额外订阅 `card.action.trigger` 并发布 |

在机器人私聊发送向导显示的一次性配对码，再回到终端确认身份。组织接入可在初始化后从工作台配置，组织成员无需逐人配对。

## 五个命令入口

| 命令 | 用途 |
| --- | --- |
| `namo init` | 初始化、配对；`init --import` 导入 OpenClaw 配置 |
| `namo login` | 登录 Namo 独立的官方 Codex 账号 |
| `namo start` | 前台运行接收服务 |
| `namo service <操作>` | `install / start / stop / restart / upgrade / uninstall` |
| `namo ui` | 打开本机工作台，不启动飞书接收端 |

所有入口支持 `--config /absolute/path/config.json`；语言使用 `--lang system|en|zh-CN` 或 `NAMO_LANG`。完整帮助为 `namo --help`。维护步骤见[运维指南](operations.md)。

## 工作台

`namo ui` 自动打开浏览器，终端进程需保持运行；Ctrl+C 关闭，页面授权两小时后失效。侧栏可切换中英文，任务原文与日志不翻译。

| 页面 | 常用操作 |
| --- | --- |
| 概览、任务、会话 | 查看统计、搜索筛选、执行证据、停止任务、核对异常 |
| 助手 | 设置身份、回答风格和是否使用本人档案 |
| 记忆与档案 | 查看、纠正、停用、删除记忆；编辑称呼、语言和时区 |
| 项目管理 | 配置项目目录、权限、模型、并发和时限 |
| 连接设置 | 组织接入、GitHub 账号、连接诊断、日志、推送审批、OpenClaw 来源检查 |

配置先保存，再确认应用；有在途任务时不自动重启。连接诊断不调用模型，“测试 Codex 回复”需确认并可能消耗账号额度。

## 聊天命令

普通文字即可发起任务，群聊默认需要 @ 机器人。以下为常用命令，其他命令用 `/help` 查询。

| 目的 | 命令 |
| --- | --- |
| 查任务 / 停止 | `/tasks`、`/task N-编号`、`/cancel [N-编号]` |
| 切项目 / 上下文 | `/project [项目名]`、`/new`、`/session [W-编号]` |
| 补充要求 | `/amend N-编号 内容`，或引用本人任务消息 |
| 回答提问 | 引用问题回复、点击选项，或 `/resume WAIT-编号 回答` |
| 提供材料 | `/material 内容` 暂存，随后 `/run 要求`；单独附件也先作为材料 |
| 交付文件 | `/deliver N-编号 相对路径`，或 `/run --deliver 相对路径 -- 要求` |
| 档案 / 记忆 | `/profile`、`/memories [查询]`；修改也可在工作台完成 |
| 用户默认模型 | 私聊 `/model` 查看，`/model 模型ID` 设置，`/model default` 跟随服务默认；也可在工作台「记忆与档案」中设置 |

用户模型优先于项目管理中的服务默认模型。显式选择在任务接受时固定，排队、执行及等待恢复不会随之后的设置变化；未指定模型时，在第一次运行前读取 Codex 的有效配置或推荐默认并固定，用于等待恢复。默认模型暂不可解析时任务不会执行。模型列表由官方 Codex 返回，候选项不保证账号有权使用；模型不可用时任务会失败，不自动切换模型重跑。后台记忆提取仍使用服务配置的模型。
| 异常 / 身份 | `/issues`、`/issue 编号`、`/whoami` |

取消不会撤销已经发生的文件或外部操作。发送结果不明时先核对，避免重复执行。

## 材料与记忆

材料输入支持合并转发文字、直接发送的 UTF-8 文本 / Markdown、PNG / JPEG。图片可用于新任务、排队补充及等待恢复，运行中追加附件暂不支持；合并转发子消息中的附件、PDF / Office / 音视频解析也不支持。

经明确授权可交付任务内的文本、Markdown、PDF、PNG / JPEG / GIF / WebP；支持发送不代表支持解析。只接受确切项目相对路径，拒绝项目外、符号链接和敏感文件。

自动记忆默认从直接对话中提取有来源的长期事实，使用独立 Codex 调用，可能消耗额度。临时要求留在任务上下文；迁移材料需审阅后启用。本人档案须在助手设置中显式开启使用，私人内容不会因此向群聊公开。

纠正、停用或删除会影响后续检索；既有原生 session、历史消息和备份不会一并抹除。需要干净上下文时使用 `/new`。
