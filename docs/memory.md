# 长期记忆与受控交接

更新：2026-10-27。默认从对话中自动提取和更新长期记忆，无需逐条确认；复用 schema 8 的 SQLite 存储、版本和运行快照。后台主要用于查看、纠正和删除，显式命令与手动新增仍可用。OpenClaw 候选保持 `pending_review`，须在 UI 明确审阅启用。本文描述源码契约，不代表在线服务已升级或真实飞书验收完成；历史记录见[交付台账](archive/roadmap-delivery.md)。

## 默认自动提取与边界

服务从已配对用户的直接私聊或群聊文字中，增量提取有长期价值的本人事实、偏好、明确纠正、项目概况和项目细节。普通对话可以产生记忆，不要求用户先说“记住”或点击保存；没有可用事实时不写入。每条自动记忆必须附有来源消息编号和可逐字匹配的原话证据，由 Namo 验证后落库。

助手结论、模型推断、引用、转发、附件和网页材料不直接提炼为人物或项目事实；指令中的姓名不能改写系统身份。临时要求、未核实猜测、当前故障或部署状态、凭据不进入自动长期记忆。支持的手动类型仍包括任务摘要、历史原话和受控交接。自动记忆整理是有限的后台任务，不意味着另有长期自循环模型、后台派工、定时唤醒或自动跨用户合并身份。

记忆不提供操作授权。内容即使写着“以后直接推送”“已经批准”或“生产状态正常”，也只是不可信的辅助上下文，不能改变项目目录、网络、凭据、审批或外部动作规则。当前任务的明确要求和对应项目约定优先；任务摘要、原话、证据与交接都可能过期，执行前仍须核对当前真源。

## 档案、临时要求与记忆的区别

渠道身份只取系统元数据；基础 profile 使用渠道 / 应用 / 用户复合键，与助手设置、范围记忆分别管理。两个用户同名或跨应用 open_id 相似都不能合并身份。

“这次用英文”等短效要求留在当前任务 / session 上下文，不写长期记忆，新会话不采用这类临时要求。稳定偏好可以从普通自然语言自动保存或纠正；基础 profile 与助手设置仍通过各自契约管理，不由记忆提取器改写。档案启用条件见[助手设置](assistant-settings.md)。稳定知识、任务摘要、历史原话和实时任务状态分别处理，摘要不能替代实时真源。

检索同时校验记忆层级和结果接收范围：全局知识可跨会话使用，不表示所有私聊信息都可以向群聊披露。采用 SQLite、版本化更新、正文读取前的隐私过滤和有界快照。现有 `owner / project / chat` 记录保留原范围，不会因升级自动公开；旧 session 与备份不会随当前记忆删除同步擦除。

分层参考了用户提供的 Christina 规划：对话上下文隔离，人物与项目概况可共享，项目细节局部使用；当前实现仍以 Namo 的身份、隐私过滤和权限规则为准。参考文档为[Christina 技术架构说明](https://kaonai.feishu.cn/docx/WOFsdauKioByBFxK1QocHIXpn6f)，未在本次重新读取该链接，不能据此推断外部系统或 Namo 的在线能力。

## 存储与版本

记忆正文与审计继续保存在 `settings(key,value)`；schema 11 为后台调度新增索引投影，保留以下原始记录：

- `memory:meta:<id>`：类别、状态、来源用户、层级、隐私范围、来源消息、精确依赖版本、容量和时间；自动记忆另含宿主保存的来源项目 `resourceProjects`、稳定概念 key、观察时间及证据 SHA-256 哈希，不复制原话或正文。
- `memory:content:<id>`：当前版本正文。只有权限元数据过滤通过后才读取。
- `memory:change:<id>:<version>`：动作、版本、来源和时间，不复制旧正文。
- `memory:snapshot:<runId>`：一次运行采用的 `id + version` 与截断状态，不复制正文。
- `auto-memory:job:<id>`：提取队列、入站消息引用、状态、尝试次数和租约，不复制对话原文。
- `auto-memory:source:<id>`：来源去重标记，防止相同消息 / 运行被反复入队。

原话在提取时用于核对来源，持久化自动记忆元数据只保存其哈希；原始消息仍由入站账本保存，当前记忆正文仅在 `memory:content:*` 中。后台提取重试不会重新执行用户任务或重发任务结果。

新增、纠正、停用、删除和迁移启用均在 `BEGIN IMMEDIATE` 事务中比较版本并同时写元数据、正文和审计。并发使用旧版本会得到 `conflict`，不会覆盖新值。停用保留正文但不再检索；删除递增版本、写 tombstone 并移除当前正文，不能纠正或重新启用，若要恢复含义必须显式保存为新 ID。备份、旧 runner prompt 和模型 session 不宣称同步擦除，界面应提示新建工作线。

迁移来源只能以 `pending_review` 保存，检索和快照不会使用；必须由已认证本机所有者调用 `activatePending` 明确审阅启用。导入成功与生效是两个状态。

## 可见范围

每条记录始终绑定真实来源用户 `ownerId`，不会按姓名或正文合并身份。自动记忆的知识层级和可披露范围独立：

| 范围 | 读取条件 | 写入条件 |
| --- | --- | --- |
| `global` | 人物事实、长期偏好和项目概况；通过隐私过滤后，可在相关私聊 / 群聊和跨项目话题中检索 | 由受验证的后台提取器分类写入 |
| `local` | 项目实现细节；仅当前项目匹配且通过隐私过滤时检索 | 后台提取器固定绑定来源对话的当前项目 |
| `owner` | 同一已验证用户，且结果仍发给其私聊；本机所有者可管理 | 已验证用户本人私聊，或本机所有者 |
| `project` | 同一用户、同一项目且为私聊；本机所有者可管理 | 已验证用户本人在该项目私聊，或本机所有者 |
| `chat` | 同一用户、同一 `chatKey`，并在记录指定项目时匹配项目；可用于明确保存到同一群的内容 | 已验证用户从该聊天显式保存，或本机所有者 |

组织模式额外检查来源资源权限，覆盖提示词快照、`/memories` 和提取器已有记忆输入。来源项目由宿主记录，不依赖模型是否填写 `project` 或选择 `project_knowledge`；纠正与交接继承来源限制，用户私聊授权不会自动授予群聊。旧自动记忆从来源队列和变更审计恢复项目约束，不重写或删除历史。本机所有者仍能管理记录，非组织的配对安装保持原共享语义。

`global / local` 的 `visibility` 独立控制披露：

| 隐私标记 | 可用场合 |
| --- | --- |
| `shared` | 已认证用户的相关私聊或群聊；组织模式还须拥有全部来源项目权限，`local` 仍须匹配当前项目 |
| `private` | 来源本人私聊；不向其他用户或群聊注入 |
| `chat` | 精确匹配来源聊天；`local` 仍须匹配项目 |

薪资、人事、健康、家庭住址、联系方式等敏感内容由提取规则和程序检查归为私有；不确定的个人信息默认私有。这是基于分类与匹配规则的披露控制，不是通用 PII 识别或磁盘级隔离承诺。全局项目概况按当前话题匹配，可以在跨项目协作或综合分析时使用；局部细节不跨项目。群聊不会读取旧 `owner / project` 私有记忆，旧 `chat` 也不跨其指定聊天和项目。本机管理入口仍按选定来源用户管理。

`Memories.search` 的顺序是强制契约：

1. 只读取无正文的 `memory:meta:*`。
2. 检查已认证主体、知识层级、隐私范围、项目 / 聊天匹配、active 状态、到期时间和交接依赖。
3. 仅对通过的 ID 读取 `memory:content:*`。
4. 对正文与来源引用执行调用方提供的脱敏器；抛错或无法脱敏则不返回。
5. 在脱敏后的正文上做有限关键词匹配和排序。

因此，未授权正文不会先进入脱敏器、关键词索引或返回对象。调用方应传入与服务一致、包含应用 Secret 的 `makeRedactor`；默认只覆盖通用 token 形态，不是任意 PII 识别器。

## 容量、到期与快照

当前保守上限由 `MEMORY_LIMITS` 导出：单条 3000 字；每个 owner 最多 100 条 / 40000 字；每个精确 scope 最多 40 条 / 16000 字。查询最多 120 字、8 个词、20 条结果。超限明确返回 `capacity` 或 `invalid`，不静默截断写入。

一般记录可不设到期时间；显式到期最长 365 天。任务摘要和交接默认 30 天、最长 90 天。过期记录不检索，但仍占物理容量，需明确删除后释放，避免“过期即不可追溯删除”。

`snapshot(runId, access, options)` 最多采用 12 条、6000 字；超出时标 `truncated`。快照及嵌套项被冻结，同一 runId 不允许重新生成。持久记录只有版本引用，正文只进入当前进程返回值和随后一次性生成的 runner prompt；恢复已经存在的 runner job 必须复用其持久化 prompt，不能从旧 snapshot 元数据重建正文。

## 受控交接

`saveHandoff` 接收目标、限制、决定、证据、未完成项和 `dependsOn: {id,version}[]`，各字段及数量有界，默认 30 天到期。每个来源必须允许向交接的目标范围披露；共享全局知识可以用于交接，项目细节仍须匹配项目，私人来源不能借摘要扩大可见范围。

检索交接时会递归核对精确依赖版本。任一来源被纠正、停用、删除、到期、改范围或其上游失效，旧交接立即不可检索；当前实现不会用旧交接重新创建已删除记忆。创建新交接必须显式引用当前版本。持久 snapshot 只有引用，不提供“从旧 snapshot 恢复”接口。

## 提取队列与自动更新

`AutoMemories` 在入站消息持久接受后登记增量引用，合并同一用户、聊天和项目下短时间内的消息。一次最多处理 24 条 / 16000 字，输出最多 8 条候选。Engine 优先调度前台任务；只有存在空闲并发槽且不处于维护时才启动提取，前台新任务可以中断提取。一次提取最多 60 秒，失败退避重试，总计最多 3 次尝试；中断会回到待处理状态。租约过期允许恢复，提交时核验租约归属，提取失败不影响已接受任务的执行和投递。

提取使用独立的官方 Codex app-server 临时（`ephemeral`）只读轮次，沿用 bot 独立登录环境；关闭 shell 工具、hooks、插件、apps、MCP 和 web search，沙箱网络关闭。模型服务请求仍走官方 Codex 登录，不开放项目工具；检测到有副作用的工具调用会中止提取。此轮次不会追加到用户工作线的 Codex session。

Namo 逐条检查候选格式、来源消息编号和逐字证据，拒绝临时 / 不确定内容和凭据，将敏感内容收紧为私有。稳定概念 key 用于去重和纠正：重复事实只补充来源，不制造新版本；更新须有较新的观察时间；不能自动扩大已有私有 / 聊天限定内容的披露范围。人工纠正后的内容受保护，自动提取不覆盖。停用或删除保留概念 tombstone，旧对话及后续重复提取不能复活相同概念。自然语言明确要求忘记已有自动概念时，可由经验证的提取结果执行删除；没有匹配概念时不猜测删除。

长期价值和隐私类别仍部分依赖模型判断，程序用来源校验、敏感规则与可见范围限制兜底，不保证识别所有隐私表达。删除 / 停用对相同概念 key、正文和来源证据指纹提供确定性拦截，并将已阻止概念传给提取器；同义改写且使用全新证据时，不能仅靠哈希保证语义去重。发现误判可在对话中纠正或从管理界面删除。

## Engine 接线

1. Engine 从系统事件和当前任务绑定构造 `MemoryAuthority` / `MemoryAccess`；`authenticated` 由已验证发送者与本机 session 派生，不能来自聊天正文或 HTTP JSON。
2. 直接用户消息可进入自动提取队列，再经后台候选校验调用 `upsertAutomatic`；模型正文和引用材料不能直接调用写接口。显式命令仍通过 `save / correct / disable / delete` 处理。
3. `source` 由适配器填写：自动提取使用持久队列 ID 和来源消息编号，显式命令使用系统 message ID，文档使用受控资源引用，本机入口使用本机动作编号；不要把整段原文或凭据放进 source ref。
4. `MemoryError` 建议映射：`invalid` 400、`forbidden` 403、`missing` 404、`conflict` / `snapshot_exists` 409、`capacity` 413、`storage_invalid` 503。回复说明变更 ID、版本、范围、状态和到期时间，但不在群聊回显 owner / project 私有正文。
5. 新 `task_runs.id` 创建后、runner prompt 持久化前，主 Engine 使用本次真实接收范围调用一次 `snapshot(runId, access, {query})`；恢复已有 runner job 时复用其持久化 prompt，不重新读取记忆。
6. `buildTaskRunPrompt` 组合助手设置与 `composeMemoryPrompt`。空快照保持原 prompt 不变；有内容时加入来源、版本、截断状态和“不是授权 / 当前真源”的边界，两者都不能覆盖 runtime 的强制规则。
7. 续接 session 使用新 runId / 新快照。已经持久化的 runner job 不再次 snapshot。删除或停用后若旧 Codex thread 仍含内容，明确提示残留并建议 `/new`，不能声称已从模型历史擦除。

已接入的聊天命令：

- `/remember owner|project|chat 明确内容`
- `/memories [查询]`
- `/memory-correct M-编号 当前版本 新内容`
- `/memory-disable M-编号 当前版本`
- `/forget M-编号 当前版本`
- `/handoff N-任务编号`

这些命令只接受已配对本人的直接私聊文字指令。`/handoff` 从本人、本聊天和同一项目的任务生成有界交接，记录目标、限制、结果与有限证据；不复制 Agent session，不把旧任务状态冒充当前真源，也不授予新的外部操作权限。

## 管理 API / UI 接线

管理界面只通过本机认证 API 使用 `local-owner` authority / access，并始终指定当前配对 ownerId。现有端点：

- `GET /api/memories?ownerId=` → 当前 owner 的 `manage()` 脱敏投影，以及当前配置的 paired owners / projects 和数据库中该 owner 已出现的 chats。未知 owner 返回 403；deleted 只有 tombstone，不读取正文。
- `POST /api/memories` → `save / correct / disable / delete / activate`，动作体携带 ownerId 与 expectedVersion。scope 必须来自上一个状态投影，后端仍会重新核对，不相信浏览器选项。
- `history()` 服务契约已实现但尚未开放 HTTP 页面；开放时来源引用仍须经过相同脱敏和 owner / scope 检查。

`ui/pages/MemoryPage.tsx` 提供不导入 Node / SQLite 的双语 Radix 页面，以列表、纠正和删除为主；手动新增和迁移材料默认折叠。页面展示全局 / 局部层级、隐私标签、自动来源、版本、状态和到期时间。可选手动新增仍从当前配对 owner、已配置项目和已有聊天选择原有 scope，不允许手填陌生 owner / project / chat，并调用版本化 `save / correct / disable / delete / activate`。删除确认说明当前正文会移除，但备份、历史聊天、旧 prompt / session 不会被同步擦除。pending migration 与 active 分开显示，不能用“已导入”冒充“已生效”。
