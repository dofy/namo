# 运维指南

日常状态、诊断与日志从 `namo ui` 查看。运行版本以工作台侧栏的版本信息为准，源码版本和历史验收记录不能代表当前服务。

## 配置与权限

配置优先级：`--config` → `NAMO_CONFIG` → 当前目录的 `config.local.json` → 系统用户目录。`NAMO_HOME` 可指定隔离实例；默认目录为 macOS `~/Library/Application Support/Namo`、Linux `~/.config/namo`（遵循 `XDG_CONFIG_HOME`）、Windows `%APPDATA%/Namo`。

- 使用初始化向导或工作台修改配置，字段示例见 [config.example.json](../config.example.json)。保存会备份并检查并发修改；保存与应用分开，在途任务不随普通设置变更而重启。
- 模板默认只读。只授权具体项目、必要的命令联网和本地提交权限，不开放整个主目录；配置、数据、认证和日志保持私有。
- Codex 使用独立登录目录；重新认证运行 `namo login`，不要复制个人认证或改用第三方网关。
- 组织模式校验租户身份与应用可用范围；新成员默认隔离工作区，本机项目另行授权。个人私聊授权不代表允许向群聊披露结果。
- 旧工作线保留项目绑定。权限撤销后不能靠续接绕过；需要重新开始时发送 `/new`，旧历史保留。

## GitHub 连接

在**连接设置 → GitHub**选择本机 `gh` 登录或独立令牌，并绑定一个已配对的本人飞书账号，然后保存、应用。

| 场景 | 权限 |
| --- | --- |
| 已准入群聊 | 只读访问所选账号可访问的仓库，包括 PR 审查和检查等待 |
| 本人私聊 | 按明确请求使用账号具备的 API 权限；不扩大本机目录或 shell 权限 |
| 其他私聊 | 不借用该账号 |

切换本机 `gh` 当前账号不会自动改绑；重新保存才能换账号。“仅公开仓库”停用账号访问。旧仓库授权配置在显式替换前保持原规则。PR 审查与检查等待不自动评论、推送或合并；写请求结果不明时先只读核对，不能换请求编号重试。

## 异常处理

| 现象 | 操作 |
| --- | --- |
| 无法收消息 | 连接设置运行诊断；核对应用发布、事件、权限、可用范围和是否有重复接收端 |
| Codex 未登录 | 本机执行 `namo login`，再运行诊断 |
| 等待补充 | 回答原问题或取消；不要新发同一任务来绕过等待 |
| runner 失联 | 工作台核对进程、后代进程和实际效果，再解除占位；不自动重跑 |
| `delivery_unknown` | 先在飞书核实；工作台填写依据后确认已收到、仅重发保存的结果分段或放弃 |
| `delivery_failed` | 修复明确的权限 / 配置错误，再决定如何处理已保存结果 |
| 配置冲突 / 页面过期 | 刷新并重审；授权过期时重新运行 `namo ui` |

平台接受消息不等于用户收到或已读。核对只补记事实或处理已保存结果，不重新调用模型；取消也不回滚已发生的操作。日志按需读取固定文件末尾，每份最多 80 行 / 64 KiB，并遮蔽已知凭据。

## 安装、升级与回退

`namo service install` 安装并启动 macOS 后台服务。开发构建不改变服务的固定发布快照；`start / restart` 继续使用已登记版本，`uninstall` 保留配置、数据和登录。

升级前先完成或取消全部任务，并核对失联运行、等待和未完成投递。**停止接收服务不等于停止独立 runner。**

```sh
namo service stop
# 在工作台确认服务停止，任务、等待、runner 和投递均已收口
namo service upgrade
namo service start
```

升级及对已有数据重装都要求空闲检查与可验证备份通过，才允许切换登记；失败保留原登记，不自动启动。当前升级入口只接受 schema 13，旧开发库不再自动迁移。新服务启动后核对连接、版本、历史数据与真实收件。

**旧测试库重建（v0–12 → v13）：** 停止接收服务并确认没有运行中的 worker；备份数据目录后，将 `bot.sqlite` 及存在的 `bot.sqlite-wal` / `bot.sqlite-shm` 一起移至备份目录，保留配置及 `codex-home`。再安装 / 启动新版本创建空库，复验首个任务与工作台。历史任务、记忆和回执不会导入新库；程序不会替你清空旧库。

备份使用 SQLite backup 并验证内容；完整停机备份需保留配置、整个数据目录和独立登录目录。不能只复制正在写入的 SQLite 主文件而忽略 WAL。回退需选择兼容快照并保留新增数据；不支持跨 schema 逆迁移，也不能用旧库覆盖新消息。启动器拒绝缺失、被改动或登记不一致的快照。

## Git 推送审批

先在本机配置的 `gitApprovals` 中明确设置 `gitBin` 和允许的远端，例如：

```json
{"gitApprovals":{"gitBin":"/usr/bin/git","remotes":[{"name":"origin","url":"git@github.com:owner/repo.git","transport":"ssh"}]}}
```

配置合并进现有文件，不覆盖其他字段。进入**连接设置 → 运行与维护 → Git 推送审批**，选择成功任务与分支，生成预览，核对项目、提交和远端后批准，再单独确认执行。结果不明时“核对远端”只读检查，不重新推送。

只支持干净工作区的确切提交与预配置分支，不支持 force、tag、删除分支或部署；自定义 hook、Git LFS 过滤器等会被拒绝。这是该入口的有限保护，不能约束通用联网工具的所有外部操作。

## OpenClaw 导入

工作台可只读检查来源；实际导入运行 `namo init --import`。目前只接受标准 JSON、版本 `2026.10.6` 的普通 `openclaw.json` 文件，需明确选择实例和应用。其他版本、JSON5、SecretRef 等转人工处理，不猜字段或解析来源凭据系统。

导入前审阅冲突、白名单、工作区和候选材料；默认收紧权限，不导入模型认证、网关、插件、任务或 session。候选记忆先暂存待审阅，不能自动注入。

导入只保存配置并输出人工切换说明，不会停启 OpenClaw。完整接管 / 回退尚无管理入口：先明确目标应用，处理在途工作并人工停用旧入口，核对双方都未接收后再启动 Namo；Webhook 还需停用旧回调并切为长连接。以同一应用真实收发及用户确认验收。回退先停 Namo，再恢复原入口，保留期间新增数据，始终避免双接收端。

## MCP 连接

在工作台 **连接设置 → MCP 连接**中添加公网 HTTPS 的 Streamable HTTP MCP。保存连接 ID、地址和使用范围后，可选择“登录授权”，或填写 Namo 专用 Bearer 令牌；无需授权的服务可匿名连接。OAuth 会根据服务元数据发现授权服务器，使用 PKCE 和一次性回调；可选地指定以空格分隔的权限范围，留空由服务决定。令牌保存在本机私有数据目录并在需要时刷新，不使用 Codex 的凭据。动态客户端注册及标准授权服务器发现是此版本的登录前提；授权服务器的授权、注册和令牌端点须位于同一 HTTPS 来源。

也可以从 Codex 用户配置中选择导入远程连接。导入仅复制名称和不带查询参数的地址，默认停用且没有访问对象；不导入凭据、环境变量或本地命令，也不读取插件内部的连接。当前不支持地址中的查询参数、本地和内网地址、STDIO 或自定义请求头。网络连接会检查 DNS 解析结果并拒绝重定向。旧 Linear 配置会以普通远程连接读取，保留原只读地址、授权范围和可用的已有凭据；如刷新失败可重新登录授权。

通用远程连接提供的每个工具调用都需要任务发起人在同一会话中单独确认，即使服务器将工具标为只读。飞书会展示连接地址、工具、完整参数和一次性审批编号；使用 `/mcp-approve MA-编号 --confirm` 批准，或 `/mcp-reject MA-编号` 拒绝。`/mcp-status MA-编号` 可查看状态。审批最长有效 10 分钟，并受任务自身时限约束；配置、权限或工具定义变更会阻止执行。执行中断时不要重复批准，先在外部服务核对结果。此审批保护的是 Namo 管理的 MCP 调用，不能替代其他已授权网络或本地执行能力的访问控制。

授权可限定成员私聊、群聊及 Namo 项目。项目限制决定哪些 Namo 任务可用连接，并不限制外部账号在其服务中能访问的资源。群聊授权允许该群接收账号有权访问的内容。默认空名单不开放访问；外部账号本身的权限仍是实际资源范围。

保存后按工作台提示应用配置，新连接对新任务生效；撤销权限在调用和结果交付时重验。已有工作线未注册该工具时需在飞书发送 `/new`；撤权前读入的旧上下文不能自动清除。配置 MCP 连接后，Codex 原生插件和应用会被关闭；如 Codex 配置中仍有启用的未纳管 MCP 服务，任务会拒绝启动，需在独立 Codex 配置中先停用它们。GitHub 原有连接和审查流程不受此设置替换。
